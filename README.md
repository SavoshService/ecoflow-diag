# EcoFlow Діагностика — Savosh Service

Android-застосунок для сервісної діагностики батарей станцій EcoFlow усіх поколінь.
Входить у той самий акаунт, що й застосунок EcoFlow (ключі розробника не потрібні),
підключається до хмари EcoFlow і зчитує дані прямо з BMS кожної батареї.

## Що показує

Для кожної батареї (основної та кожної додаткової):
- **SOH** — за BMS і за вивченою ємністю (fullCap / designCap), вердикт кольором;
- **ємність** в А·год і Вт·год (фактична / номінальна);
- **кількість циклів** і оцінку використаного ресурсу за паспортом моделі (напр. Delta Pro — 3500 циклів до 80%);
- **номінал за BMS і за паспортом** з поясненням різниці (Delta Pro: 80 А·год × 48 В = 3840 проти 3600 Вт·год);
- **хімію** (LiFePO4 чи Li-ion NCM) і кількість послідовних груп — визначається за напругами;
- **напруги груп**: мін/макс, розкид у мВ, найслабша група, графік відхилень від середнього
  (колір за абсолютним порогом: ≤20 мВ норма, ≤50 мВ увага, >50 мВ погано);
- **коди BMS**: bmsFault, bqSysStatReg (біти тривог AFE 0–5, біт 7 CC_READY — не тривога),
  errCode/allErrCode списком бітів, силові ключі (mosState) з поясненням («заряд зупинено лімітом 80%»);
- поля, які BMS **не передає** (packSn з нулів, V0.0.0, 0xFFFFFFFF тощо) — окремим списком, а не як дані;
- температури елементів і MOSFET, датчик вологи (3-тє покоління), накопичену енергію BMS.

**Статус:** «Погано» — лише за підтвердженими проблемами (відмова BMS, біти тривог AFE, втрата зв'язку з BMS,
низький SOH, великий розкид, температура). Незадокументований код без інших ознак — «Увага».

Для станції: режим роботи (байпас/UPS, заряд, розряд), ліміти заряду, потужність AC-заряду, X-Boost;
захисти й зв'язок (EMS, зв'язок з кожною BMS, дозвіл заряду/розряду, коди інвертора/PD/MPPT);
напрацювання; енергію за весь час (AC-лічильники включають транзит у байпасі, тому «еквівалент циклів»
станції не рахується); прошивки (PD, інвертор, MPPT, Wi-Fi, BMS).

**Власна база кодів:** біля незадокументованого коду — «✎ Моя примітка до коду». Примітка зберігається
на телефоні й показується для цього коду на всіх станціях і в технічному звіті.

**Історія кодів і захистів:** поки відкрита діагностика, кожна поява/зникнення коду BMS, втрата зв'язку з батареєю,
помилки інвертора/PD/MPPT записуються з часом і станом станції (SOC, режим, струм, температура). Зміни, що сталися,
поки застосунок не був підключений, позначаються «між перевірками». Зберігається до 300 подій на станцію,
останні 30 — у технічному звіті. Зміни між двома нормальними станами (EMS зупинила заряд на ліміті) не пишуться.

**Звіти** — кнопкою «Поділитися»: «Звіт клієнту» (без службових полів і кодів) або «Технічний звіт» (усе).
Останні звіти кожної станції зберігаються в списку. «Сирі дані» показують усі параметри від станції.

## Безпека входу

- Логін і пароль надсилаються лише на сервер входу EcoFlow (api.ecoflow.com / api-e / api-a) через HTTPS
  з перевіркою сертифіката; дані станцій — з MQTT-сервера EcoFlow через TLS. Інших з'єднань немає:
  ні власного сервера, ні реклами, ні аналітики.
- Програма лише читає дані: команд керування станцією не надсилає.
- «Запам'ятати пароль» — пароль шифрується ключем Android Keystore (AES-256/GCM); без галочки не зберігається.
  Пароль зі старих версій (відкритим текстом) автоматично переноситься в шифроване сховище і стирається.
- Резервне копіювання програми в хмару вимкнене (`allowBackup=false`). Пароля й токенів у журналі немає.
- На екрані входу є картка «Пароль бачить лише EcoFlow» і кнопка «Детальніше про безпеку».

## Підтримати автора

Кнопка «☕ Підтримати» на екрані станцій і пункт меню на екрані діагностики відкривають банку Monobank
(`DONATE_URL` у `ui/Support.kt`; порожній рядок — кнопки зникають).

## Підтримувані станції

| Покоління | Протокол | Приклади |
|---|---|---|
| 1-ше | JSON | Delta Max, Delta Pro, Delta Mini, River Max/Pro (+ додаткові батареї) |
| 2-ге | JSON | Delta 2, Delta 2 Max, River 2 / 2 Max / 2 Pro (+ додаткові батареї, у т.ч. Delta Max EB) |
| 3-тє | protobuf | Delta 3 / 3 Plus / 3 Max, Delta Pro 3, River 3 |

Покоління визначається автоматично за форматом даних, тож працюватимуть і моделі, яких немає в таблиці.

## Як користуватися

1. Станцію клієнта додайте у свій акаунт EcoFlow (скидання IoT-кнопкою → додати в застосунку EcoFlow).
   Станція має бути **онлайн через Wi-Fi**.
2. У застосунку увійдіть тим самим email і паролем. Сервер — «Авто» (якщо не пускає — «Європа»).
3. «Додати станцію» → серійний номер (наклейка або налаштування пристрою в застосунку EcoFlow).
4. Натисніть на станцію — за 5–15 с з'являться дані.
5. Після сервісу видаліть станцію зі свого акаунта EcoFlow, щоб клієнт додав її назад.

Якщо щось не працює — меню «⋮» → «Журнал підключення» → поділитися журналом.

## Збірка й оновлення

Репозиторій з кодом — **приватний**. Збірку робить GitHub Actions автоматично при кожному
`git push`: збирає підписаний APK і публікує його в **окремий публічний** репозиторій релізів
`ecoflow-diag-releases → Releases → latest → savosh-ecoflow-diag.apk`. У застосунку приходить
сповіщення про нову версію, і оновлення качається та ставиться в один дотик.

**Схема безпеки:**
- Код — у приватному репозиторії; публічний репозиторій містить лише готові APK.
- Ключ підпису й паролі — тільки в GitHub Secrets (`KEYSTORE_B64`, `KEYSTORE_PASSWORD`,
  `KEY_ALIAS`, `KEY_PASSWORD`), у коді їх немає.
- Публікацію релізу в публічний репозиторій робить токен `RELEASES_TOKEN` (GitHub Secret).

## Технічно

- Вхід: `POST https://api.ecoflow.com/auth/login`, далі `/iot-auth/app/certification` → облікові дані MQTT.
- MQTT (TLS 8883): підписка на `/app/device/property/<SN>` і `/app/<userId>/<SN>/thing/property/get_reply`,
  запит повного знімка в `.../thing/property/get` (JSON `latestQuotas` або protobuf get-all для 3-го покоління).
- Розбір protobuf зроблено вручну (без бібліотеки), номери полів — з відкритих описів спільноти
  (hassio-ecoflow-cloud, ha-ef-ble).
- Пароль зберігається лише в приватних налаштуваннях застосунку на телефоні.
- Ключ підпису зберігається в GitHub Secrets (`KEYSTORE_B64`, `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD`) — у репозиторії його немає. Ключ постійний, щоб оновлення ставились поверх старої версії.
